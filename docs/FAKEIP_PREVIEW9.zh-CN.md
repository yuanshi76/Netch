日期：2026-09-24。版本：1.9.11-dns-preview.9。交付仍为单个 `Netch.exe`，保留现有安装目录。Fake-IP 默认关闭；Xray 26.3.27、sing-box 1.13.21 保持不变。

## 已实现的路径

应用查询 → Netch DNS 服务 → 经所选代理访问远程 DoH/DoT → 校验真实应答 → 分配会话虚拟地址 → 应用连接 → Netch SOCKS/HTTP 入口恢复域名 → 核心按域名规则处理连接。

采用统一的托管映射池和核心前置入口，没有直接启用 Xray/sing-box 原生 FakeDNS。这样两种核心共享生命周期，能在分配前落实“远程不能解析就报错”，并避免核心 LRU 淘汰后把旧地址交给另一域名。参考机制来自 [Mihomo DNS](https://wiki.metacubex.one/config/dns/)、[Xray FakeDNS](https://xtls.github.io/config/fakedns.html) 与 [sing-box FakeIP](https://sing-box.sagernet.org/configuration/dns/server/fakeip/)；不能把本项目实现与这些项目的默认行为视为相同。

- 设置页增加开关、IPv4 地址池、TTL、兼容域名列表。仅允许严格远程策略开启 Fake-IP。
- 默认 IPv4 池 `198.18.0.0/15`，可选其中按边界对齐的 /15～/24；IPv6 池固定 `fdfe:dcba:9876::/96`。默认 TTL 60 秒，上限 300 秒且不超过远程应答 TTL。
- SOCKS TCP、SOCKS UDP、HTTP CONNECT 与普通 HTTP 入口恢复域名；UDP 校验会话来源并把响应来源还原为应用看到的虚拟地址。原生核心只监听内部端口。
- DIRECT 通过内部“真实应答”DNS 入口解析，不再生成 Fake-IP；代理和 BLOCK 继续按恢复后的域名匹配。未知、过期或已停止会话的虚拟地址拒绝连接。
- NXDOMAIN、空应答及非 A/AAAA 保留原义。DNSSEC 请求、兼容域名及命中兼容规则的 CNAME 返回远程真实应答；兼容列表不授予本地解析权限。上游直接返回保留虚拟地址时拒绝。
- 核心退出、监听失败及保护失败保持失败关闭。两个核心均阻止未恢复的保留虚拟地址出站；Windows 外部接口的虚拟地址防护规则已实现，但其与原生 NF/TUN 的实际协作仍待验收。

## 支持条件与生命周期

| 使用方式 | 当前行为 |
| --- | --- |
| 选择性进程、共享、仅 SOCKS | 拒绝启用 Fake-IP，继续使用严格远程真实 IP |
| 全进程 Redirector | 要求 `Handle=.*` 或 `^.*$`、无绕过项、TCP/UDP 与内网过滤开启；已实现，实际验收未通过/未完成 |
| TUN | 已实现 IPv4 路径与保留地址路由；IPv6 仍阻断绕行；实际验收未执行 |

Xray 使用现有域名规则。sing-box 的 Fake-IP 路径支持完整域名、后缀、正则、关键词，以及端口、网络和协议条件，目标为 DIRECT、BLOCK 或当前代理；未实现的 IP/geodata、进程、其他节点等条件明确拒绝，不能静默忽略。

内存最多保留 32768 个映射；到期拒绝新连接，重新查询同一仍保留的域名可续期。停止后不保留域名历史。`data/fakeip-cursor.json` 只持久保存分配游标，每次预留一批地址并先落盘再回答，防止重启、崩溃或更换地址池后把旧地址分配给其他域名。

这是有限地址池：默认最多 131070 个索引，A/AAAA 共用；崩溃/重连可能跳过已预留但未使用的地址。耗尽时返回错误，需关闭 Fake-IP 使用真实 IP。**不要删除或回退游标文件来“扩容”**，也不能宣称当前具备无限循环回收或跨重启保留可用映射的能力。应用自身缓存的旧虚拟地址可能需要重新解析或重启应用。

## 11:55 断线排查

用户确认 11:55:13 停止、11:55:18 启动属于断线后的手动重连。日志没有记录此前核心退出或共享监听故障。旧版重连覆盖 `Xray.log`，普通运行期 DNS 失败也缺少记录，因此无法确认断线来自节点、外部网络、核心还是 DNS。系统事件未给出足以归因的证据。

本次修复的是经代码确认的问题，不将其宣称为已经证实的断线根因：

1. 核心日志改为当前文件加四份轮转归档，每份约 8 MiB；重连保留旧会话。主程序不再启动时清空日志，应用日志最多五份、每份约 4 MiB。
2. 日志文件无法写入时继续排空核心输出，防止日志异常终止读取后堵塞核心输出管道。
3. 单个调用者取消 DNS 请求不再把共享解析器标记为不可用、清空其他应用的缓存。
4. 运行期 DNS 全部远程备选失败时记录分类原因，限制重复日志频率，省略查询域名及报文；恢复、核心启动/PID、核心退出和主窗口停止操作均有记录。
5. 暂时不可用时每五秒经现有代理检查远程 DNS；恢复后停止后台探测。核心或监听器明确停止仍保持失败关闭，不自动重启核心、不改网卡、不启用本地解析。
