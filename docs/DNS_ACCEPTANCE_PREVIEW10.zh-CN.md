## 已确认的问题与修复

13:48 的全进程测试中，原生 Redirector 记录目的地址为 `[::ffff:127.0.0.1]:53`。测试核心记录 `accepted tcp:127.0.0.1:53 [mixed >> proxy]`。这说明本机 TCP DNS 没有遵守模式中的“不拦截回环连接”，而被交给远程出口。测试失败发生在 HTTPS 检查之前。

旧原生规则把 IPv4 地址 `127.0.0.1` 与 `/8` 掩码组合，且 IPv6 仅列出 `::1`，未覆盖双栈 socket 的 IPv4 映射地址。修复统一覆盖 `127.0.0.0/8`、`::1/128` 和 `::ffff:127.0.0.0/104`。

为保持单 EXE 替换，`NfLoopbackPolicy` 在 Redirector 成功初始化后，通过安装目录已有 `nfapi.dll` 的 `nf_addRule` 导出加入优先的放行规则；规则失败则明确中止启动。仅在模式未要求拦截回环时使用。83 字节结构布局按现有头文件的单字节打包定义构造，隔离测试覆盖地址分类和非回环排除。

`Redirector.cpp` 同步修正供后续原生构建使用，但本次没有编译或替换原生 DLL。14:24–14:25 的真实驱动复验已验证兼容调用后的 TCP DNS 和 HTTPS 路径；纯规则分类测试与这一实际结果分别保留。

## TUN 路由生命周期

`OwnedRouteJournal` 在路由创建前，将网卡 GUID、目标前缀、下一跳和 metric 持久保存到 `data/tun-owned-routes.json`。无法保存则不修改路由，已存在的路由不被接管。正常停止或下一次启动读取记录，只有完整元组仍匹配时才删除；其他程序改变的路由保留，删除失败保留记录供重试。

独立恢复进程也读取测试宿主的这份记录，防止强制结束宿主后丢失清理依据。原有仅存在内存的拥有关系已替换。控制器停止时，即使路由清理失败仍释放 TUN 组件。

四组产品回归覆盖先记录后修改、模拟崩溃后由新控制器恢复、既存/变更路由、删除失败重试、创建失败、无效记录和不可写存储。恢复脚本另有读取产品记录的替身测试。真实 WMI 查询、原生路由操作和 TUN 数据路径尚未验证。
