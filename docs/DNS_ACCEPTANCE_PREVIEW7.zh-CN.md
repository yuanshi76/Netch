# preview.7：启动时远程 DNS 连接重置的分类与有限重试

日期：2026-09-24。修复基于用户 preview.6 日志，不修改用户安装、系统 DNS、防火墙、路由或当前代理进程。

## 日志结论

08:23:11 和 08:23:13，两台配置的远程 DNS 都在 TLS 握手阶段失败，异常链为 `HttpRequestException → IOException → SocketException (10054)`。旧版统一提示“DNS 加密连接或证书校验失败”，随后停止启动。08:26:34 用户再次启动，08:26:36 完成原生组件初始化，08:26:37 进入正常运行。

这些记录确认的是远程 DNS 通道在握手时被重置，没有记录证书不可信、过期或名称不符。不能仅凭它们判断重置来自代理节点、解析器还是中间网络，也不能认定已经修复外部链路。`SecureConnectionError` 是 TLS 握手错误的总类，而不是证书失败的专用类别，见 [Microsoft HttpRequestError 文档](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httprequesterror?view=net-8.0)。

此次是出站 TCP/TLS 通道错误，区别于 preview.6 修复的本地 UDP 客户端退出通知。截图中“检测到保留的 DNS 保护”是正常的恢复记录提示，本身不是启动失败原因。

## 修复内容

- 解开内部异常链，连接重置明确显示错误码 10054；TLS 认证、HTTP 拒绝、超时和报文无效分别报告。
- 每次启动验证只对可重试的连接故障进行最多三轮远程尝试，轮间等待 500/1000 毫秒；单次验证总时限为 `min(15000, 查询总超时 × 3 + 1500)` 毫秒，包含等待时间。模式初始化前、后各验证一次，普通应用查询保持原查询预算。
- 每轮仍仅使用用户配置的远程解析器和原代理通道，不启用系统 DNS、不增加直连解析器、不降低 TLS 证书要求。
- 若一轮失败含有认证或报文校验等不可重试错误，尝试该轮配置的备用解析器后终止；有效 NXDOMAIN 或无地址应答不能被显示为启动验证成功。
- 代理停止、服务清理或取消请求会结束重试。持续失败仍停止启动并保留 DNS 防护，日志记录每轮及最终原因，不无限自动重连。

## 回归与范围

新增五组纯隔离启动测试，先在旧实现上注入与用户日志一致的嵌套 10054 异常。即使模拟通道随后恢复，旧实现仍在第一轮失败；修复后通过。覆盖恢复成功、持续失败且次数有界、认证/无效应答拒绝、取消/代理停止、停滞请求和总时限，并确认不接受本地规则或回退作为就绪依据。

**33 组完整开发回归通过**。真实 loopback TLS 测试进一步确认 DoH、DoT 的不可信证书均被启动验证拒绝，只尝试一次，不被当作暂时重置重试。其他双栈监听、UDP 客户端退出、核心配置和隔离 Xray 路由回归通过。
