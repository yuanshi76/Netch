# DNS 改造任务总结与实施状态

更新日期：2026-09-24。当前交付版本：**1.9.11-dns-preview.6**。改造前代码基线：`197a839`。

本次完成了真实 IP 严格远程 DNS、Windows DNS 保护及恢复、连续启动故障修复，并按要求删除产品内调试测试入口。交付保持为一个可替换的 `Netch.exe`。验证型 Fake-IP 属于第二阶段，尚未实现；现有证据不支持“全设备、全模式零泄露”的结论。

## 已实现的行为

- “DNS 与隐私”页提供本地解析开关，默认关闭；本地失败回退需要单独显式开启。关闭本地解析时，旧设置、模式与辅助请求不能启用隐式本地解析。
- EXE 内置 IPv4/IPv6 的 TCP/UDP DNS 监听器。远程 DoH/DoT 经专用 SOCKS 通道进入所选代理，专用 DNS 路由优先于普通 DIRECT 规则。主解析器失败只尝试备用远程解析器，全部失败返回 SERVFAIL；有效 NXDOMAIN/空应答保持原义。
- 远程 TLS 校验名称与可信证书链；禁用证书自动下载和在线吊销查询以避免额外直连，因此不提供在线吊销状态保证。DNS 查询去除 ECS/cookies 等 EDNS 客户端信息，保留 DO/CD，校验应答匹配及报文结构。
- 查询总超时默认 5 秒，并为备用解析器保留尝试时间；并发上限 128，正向缓存最多 2048 项、TTL 最长 300 秒。核心退出会清除缓存并停止成功应答；远程就绪检查绕过缓存、本地规则与本地回退。
- 严格模式下，各叶子节点必须有字面 IP 或明确的“域名=IP”映射；缺失时在修改系统 DNS 前报错。连接 IP 与 TLS SNI、HTTP/WebSocket Host 分开处理。首版未实现自动维护带来源与有效期的节点 IP 缓存。
- Xray 内部 DNS 仅连接受控 loopback 服务；DIRECT 使用 `ForceIP`，解析失败后不再调用系统 DNS。TUIC/AnyTLS 单节点使用 sing-box；不支持的混合代理链明确拒绝。订阅、下载、证书获取及域名测速遵守相同策略。
- 严格模式建立持久防火墙规则，阻断非 loopback 的 TCP/UDP 53、853、5353、5355、137，并接管网卡 DNS。保存原静态 DNS/DHCP 状态；多网卡变化重新应用保护。当前原生 TUN 仅处理 IPv4，严格 TUN 额外阻断外部 IPv6。
- 普通停止、核心故障和退出保留保护。用户选择“停止并恢复系统 DNS”才解除保护；只处理本程序拥有的规则和仍由程序管理的网卡值。恢复失败或网卡暂时缺失时保留恢复记录。
- 修复重复清理、并发日志写入、TUN 路由清理、任意结束端口占用进程、空节点配置被备份复活等问题。启动失败保留具体阶段、错误码和 `data/startup-error.log`。
- 删除应用内手动验收菜单、测试窗口、监听/断线测试入口、自检报告、会话记录和调试统计。保留正常故障日志、策略设置和恢复入口；独立开发测试仅位于 `tests`，不打包到交付 EXE。

## 启动故障修复过程

| 版本 | 已确认的问题 | 修复 |
| --- | --- | --- |
| preview.2 | 查询不存在的 Windows 防火墙规则会把 `0x80070002` 映射为 `FileNotFoundException`，被误判为缺文件 | 精确兼容两种异常映射；其他权限和系统错误继续上报 |
| preview.3 | 对已注册规则写入空 `ApplicationName`/`ServiceName` 触发参数范围错误；重复注册还会产生同名规则 | 新规则完整配置后注册，重连复用已有规则，不写可选空字段，校验规则适用范围 |
| preview.4 | 已失败的 UDP 接收任务在清理时再次抛出 995，旧服务未充分释放 | 清理幂等，先分离运行时引用，观察失败任务，确保后续资源释放 |
| preview.5 | 远程 DNS 就绪前失败，清理未初始化的 Redirector；原生 `aio_free` 中的 `WSACleanup` 破坏 Winsock，后续出现 995/10093 或误报 53 端口占用 | 串行配对初始化/释放，未初始化及重复停止不重复释放；绑定失败记录真实端点和内部原因；删除调试测试功能 |
| preview.6 | 已关闭 UDP 客户端产生的 10054 被计入共享监听器故障，第一次启动停止解析、第二次暂时可用 | 双栈设置 `SIO_UDP_CONNRESET=false`，残余客户端重置通知不计入监听故障上限；真实监听故障仍停止解析并报错 |

preview.6 的问题已在旧实现上使用八个提前关闭的临时 loopback 客户端复现；修复后覆盖双栈及主动重新开启 Windows 重置通知的四种场景，其他客户端均能继续解析。详见 [preview.6 修复记录](DNS_ACCEPTANCE_PREVIEW6.zh-CN.md)。

## 尚未覆盖与后续改进

1. 验证型 Fake-IP 的分配、域名恢复、跨会话隔离、DIRECT 真实 IP 转换及兼容性验收。
2. FastLink 关闭时的 Netch 独立出口、实际 TUN 和全局应用场景；当前共存测试不能推导这些结果。
3. 主程序真实崩溃、换网、多网卡动态变化与休眠恢复；已有保护代码不等于这些系统场景均已验证。
4. 浏览器及未接管应用自带的 HTTPS DNS。仅阻断 DNS 常用端口无法保证任意 443 流量均经过代理；保留 DIRECT 例外时不能宣称全设备覆盖。
5. 有效的原始逐包导出和长期稳定性验收。网卡计数与前后对照是有限证据，不能代替完整报文取证。

以上需要按具体范围安排独立验收。原生组件保持现有版本，不能把 DNS 防护改造描述为已解决这些组件的全部问题。完整目标见[设计方案](DNS_SECURITY_DESIGN.zh-CN.md)。

## 构建、替换与恢复

使用 Windows .NET 8 SDK，在仓库根目录执行：

```powershell
./build-replacement.ps1
# 仅在依赖已还原时使用：
./build-replacement.ps1 -NoRestore
```

脚本优先使用本地 `.build/dotnet/dotnet.exe`，也可通过 `-Dotnet` 指定 SDK；构建失败不会复制旧产物。开发测试入口和各模式影响见 [DNS regression suite](../tests/DnsRegression/README.md)。

```text

```

该校验值标识本次生成的文件，不承诺其他环境重新构建得到相同字节。EXE、SDK/依赖缓存、测试日志和构建目录均被 Git 忽略。

完全退出旧版并保留原 EXE，再将交付文件复制为 `D:\Netch\Netch.exe`，无需替换 `bin`、`data`、`mode`、`i18n`。域名节点先补全连接 IP 映射。普通停止/退出保留 DNS 保护；需要恢复普通联网或回退旧版时，先执行“停止并恢复系统 DNS”，不要直接删除仍生效的恢复记录 `data/dns-protection.json`。
